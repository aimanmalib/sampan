### Landing address runs

`land` rows are written by `tools/measure/land.ts`: the built server against mainnet with the Bring in tab on, the
real page in Chromium, and its own finisher converting what arrives. "wallet pays through WizardConnect": the test
wallet paired through the page and signed the payment only after its checkTransaction matched the landing address
the page computed. "plain payment": the owner address typed into the form, and the test wallet paid the shown
address as an ordinary BCH payment (`tools/test-wallet/send.ts`). `seconds` runs from the payment broadcast to the
server reporting the conversion; a row is ok only when the token output is found at the owner's address. Each
landing had its own owner address of the test wallet. Median of the three rows of 2026-11-15: 3.0 s.

`giveBack` rows are written by `tools/measure/give-back.ts`: a recovery card whose minimum rate is 1000 times
what the pools pay, paid from the test wallet, then finished by the public `scripts/finisher.ts` with no Sampan
server. The finisher tried the conversion first and refused it ("trade pays 62 tokens, the contract needs at
least 60000"), then returned the BCH once the coin was `returnAfter` blocks old. `seconds` includes that wait.

### Sampan Pay runs

`pay` rows are written by `tools/measure/pay.ts`: the built server on this machine against mainnet with Sampan Pay
switched on, and a small HTTPS webhook receiver beside it. Each run makes an invoice of `pay.demo.priceUsd` for
`pay.demo.merchantAddress` (an address of the test wallet), and the test wallet pays the invoice address the exact
amount as an ordinary BCH payment (`tools/test-wallet/send.ts`). The txid cell holds the payment and the conversion
that paid the merchant in PUSD. `seconds` runs from the payment broadcast to the receiver checking the webhook
signature. A row is ok only when the invoice is `paid`, both transactions are known to Electrum, the PUSD output is
at the merchant address, and the receiver accepted the signature of an `invoice.paid` event for that invoice.
"local" means the server ran on our machine, not on the live site. Exchange withdrawals were not tested.

### Notes on failed runs

- 2026-11-15 12:51 and 12:52 (PUSD to BCH): the test wallet refused to sign, as designed when its own check
  fails. Cause: its policy lowercased the `BCH` receive marker into a token id, so a sell could never pass rule 4.
  Fixed with a regression test; nothing was sent. The page's own check had passed.
- Before those rows, a stale wallet balance after a swap was traced to the Electrum server answering the broadcast
  before its index listed the new outputs. The server now waits for the index (`electrum.indexWaitMs`) before it
  answers the broadcast.
- During the Cashonize check, a wallet funded after its first scan still showed 0 BCH on the next connect: the
  server kept the empty result for its 10 minute scan cache. The cache is now 30 seconds (`wallet.scanCacheSeconds`,
  at most 60 by config validation).

`giveBack` rows are written by `tools/measure/give-back.ts`: a recovery card whose minimum rate is 1000 times

server. The finisher tried the conversion first and refused it ("trade pays 62 tokens, the contract needs at
least 60000"), then returned the BCH once the coin was `returnAfter` blocks old. `seconds` includes that wait.

### Notes on failed runs

- 2026-11-17 12:01 (first Send out, PUSD to USDC on Ethereum): step 1 (Cauldron swap `de394a4cdc306d304cf15722490d6a543f8f6b2bab5cc9c778fef0d69080dd7f`) was sent, then the measuring tool stopped before step 2 was broadcast: its own hook that saves the cost card read the txid with the wrong type. Nothing went to the route; the BCH stayed in the test wallet. Fixed in `tools/measure/out-run.ts`, and step 2 was resumed from that swap (the 12:03 row; its seconds start at the deposit signature, not at step 1).
- 2026-11-15 12:51 and 12:52 (PUSD to BCH): the test wallet refused to sign, as designed when its own check
  fails. Cause: its policy lowercased the `BCH` receive marker into a token id, so a sell could never pass rule 4.
  Fixed with a regression test; nothing was sent. The page's own check had passed.
- Before those rows, a stale wallet balance after a swap was traced to the Electrum server answering the broadcast
  before its index listed the new outputs. The server now waits for the index (`electrum.indexWaitMs`) before it
  answers the broadcast.
- During the Cashonize check, a wallet funded after its first scan still showed 0 BCH on the next connect: the
  server kept the empty result for its 10 minute scan cache. The cache is now 30 seconds (`wallet.scanCacheSeconds`,
  at most 60 by config validation).
